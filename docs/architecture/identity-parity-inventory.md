# Identity parity inventory and Rust cutover boundary

**Status:** verified legacy characterization; additive native email-OTP request, verify, self-profile, session/workspace context, sign-out, encrypted delivery, account provisioning, actor admission, platform moderation, and bounded support impersonation are implemented behind `NIBLEAF_NATIVE_IDENTITY_ENABLED=false` by default. Better Auth remains authoritative; no dashboard route has been cut over.

## Verified legacy behavior

| Area | Verified source | Current behavior |
|---|---|---|
| Session authority | `packages/auth/src/server.ts`, `apps/server/src/middlewares/auth.ts` | Better Auth reads opaque `session.token` from PostgreSQL. Every API request resolves the session/user; suspended accounts are rejected. Session carries active organization and optional support impersonator. |
| Browser client | `packages/auth/src/client.ts` | Browser client targets `/api/auth`, sends credentials, and enables Better Auth email OTP, organization, and admin plugins. |
| Password authentication | `packages/auth/src/server.ts` | Disabled. Existing `account.password` data can remain, but no password endpoint is exposed. Historical reset links redirect to passwordless sign-in. |
| Email OTP | `packages/auth/src/server.ts`, `apps/server/src/routes.ts` | Primary customer sign-in/sign-up. Ten-minute expiry, three attempts, five-minute/three-send rate limit, resend rotation, hashed code storage, required email enqueue. Admin-origin requests do not disclose non-admin accounts. |
| Google | `packages/auth/src/server.ts`, `packages/auth/src/providers.ts` | Optional only when both client ID and secret are non-blank. New social sign-up obeys `DISABLE_SIGNUP`. |
| Cookies and CSRF-relevant policy | `packages/auth/src/server.ts` | HttpOnly, SameSite=Lax cookies; Secure tracks `BETTER_AUTH_URL` HTTPS scheme. Trusted origins are configured. |
| Email verification/change | `packages/auth/src/server.ts` | OTP overrides default verification; auto-sign-in after verification. Email change uses OTP with current-email verification. |
| Account deletion | `packages/auth/src/account-deletion.ts` | Sole-member organizations go through retained-store erasure; otherwise ownership is reassigned before deletion. Rust implements a fail-closed direct-native subset (ADR-0011): zero-membership deletion and departure from shared workspaces are supported; a last-owner departure promotes the earliest other member atomically; pending starter provisioning is cancelled; worker-owned provisioning and every sole-member tenant return conflict; immutable opaque evidence remains; retained-store sole-tenant erasure is still open. |
| Organization/member hooks | `packages/auth/src/server.ts` | Prevents direct owner grants/demotion, provisions starter projects, and emits best-effort join/security notification workflows. |
| Moderation and support | `packages/auth/src/server.ts`, Prisma schema | Banned/suspended users are prevented from session creation; active request check is the backstop. Admin impersonation is one hour and has platform events. |

## Important correction to the requested parity scope

The requested native cutover now has a documented exception: per [ADR-0008](decisions/0008-native-identity-email-otp-cutover.md), email OTP is the first native contract and optional Google sign-in is intentionally disabled at cutover rather than retained through a legacy-only path. The present product is passwordless-first and has no exposed password/reset flow; Rust must not add a new password surface merely because Better Auth supports one.

## Native Rust implementation order

1. **Implemented:** Add isolated identity tables for opaque Rust sessions, hashed OTP challenges/attempts, OAuth authorization state/PKCE, and account-link receipts. Do not import raw Better Auth tokens or credentials.
2. **Partially implemented:** native opaque-session issue/authenticate/revoke, host-only cookies, exact-origin admission, CSRF validation plus exact-Origin CSRF-secret recovery/rotation for a lost browser-local proof, suspension/ban checks, native actor injection for implemented Rust feature routes, self-profile name update, active-workspace preference selection, platform moderation, and bounded support impersonation. `GET /identity/session` now carries profile facts and resolves a stored active organization only when it remains a live membership, otherwise it deterministically reports the first live membership like the legacy middleware; `PATCH /identity/profile` and `PUT /identity/session/active-organization` re-fence the exact session/account state, and the latter never grants authorization. Native moderation re-reads the live platform-admin role transactionally; it atomically fences native plus bridge sessions, terminalizes any active target-bound support context with the moderator’s exact user/session attribution, protects platform administrators from suspension, supports project takedown/restoration, and records durable operator/target/change audit facts. Native support access issues a one-hour target session, preserves the operator only in a path-scoped HttpOnly resume cookie, supports auditable end/revoke/system-expiry facts, prevents impersonated sessions from operating the platform boundary, and has a bounded cancellation-aware `FOR UPDATE SKIP LOCKED` worker reconciler. Dashboard/browser session, profile, email-change, and support-flow adapter migration remain open.
3. **Implemented behind rollout gate:** email OTP request/verify/resend state, provider-required durable encrypted delivery intent, bounded versioned current-plus-previous delivery-encryption key-ring configuration, UUID-shaped opaque request continuations for real, malformed, and rate-limited browser OTP flows, rate limits, hashed code storage, new-account policy, and asynchronous workspace provisioning. Native signup creates the ported seven-page rich starter tree and a durable automatic v1 publication request; re-delivery is idempotent. Legacy Harbor theme metadata, default add-on/audit rows, and the analytics platform event remain documented parity differences.
4. **Superseded at first cutover:** Google authorization/code/PKCE implementation is not required because ADR-0008 intentionally disables Google rather than retaining a Better Auth-only path.
5. **Partially implemented behind the same rollout gate:** two-stage native email change proves the current mailbox and then the new mailbox through distinct `verify_email`/`change_email` OTPs, encrypted durable delivery, constrained `pending_current → pending_new → completed` state, and an atomic final user-email update. Its routes require the native cookie plus API-wide Origin/CSRF admission; request and current-proof delivery-dependent paths refuse when no provider exists. Request and current-proof responses now return opaque UUID continuation handles on both real and ordinary-rejected paths, allowing a browser to progress without using database-only challenge IDs while preserving target-email anti-enumeration. Native account deletion now has a deliberately narrow direct-session implementation that revalidates and locks the account, fences pending provisioning, records immutable evidence, and safely preserves shared workspaces by transferring a departing last owner. It fails closed for worker-owned provisioning and every sole-member tenant. Dashboard/browser integration and full route/cookie compatibility migration remain open. Sole-member retained-store erasure, dashboard moderation/support-access migration, and organization hooks remain open.
6. **Open:** compatibility fixtures for actual Better Auth browser request/response/cookie behavior. Do not route dashboard `/api/auth` traffic until endpoint, cookie, status, CSRF, and state-transition matrices pass.
7. **Open:** allowlisted migration, bounded legacy-session bridge/drain, and Better Auth removal. Never dual-issue sessions blindly.

## Explicit non-goals for the first native identity slice

- Password sign-in/reset: disabled legacy behavior; adding it is a product/security change requiring separate approval.
- Reusing Better Auth secrets or serializing Better Auth session cookies in Rust.
- Changing legacy user/account/session rows in place.
- Migrating OAuth refresh/access tokens without a credential-encryption and provider-consent design.
